What is CraveDash? Course project for 24SDCS03R - SOA PROGRAMMING AND MICROSERVICES. A high-throughput multi-restaurant food ordering and fulfillment engine built to effortlessly connect hungry consumers, culinary restaurant partners, and fast delivery fleets.

Built by Team HungryDevs with Spring Boot 3.2, Spring Cloud (Eureka Discovery & API Gateway), JWT Security, and PostgreSQL (mydb), CraveDash ensures real-time digital menus, instant stock availability updates, seamless multi-item order state execution, and zero degradation during peak lunch and dinner rushes.

▶ Live Request Orchestration Sequence:
1. [Client ➔ Gateway] POST /api/orders { items, deliveryAddress, paymentMethod } + Bearer JWT
2. [Gateway Filter] Decodes JWT signature, validates role claims, injects X-Gateway-Secret & X-User-Email
3. [Eureka Discovery] Gateway resolves 'lb://order-service' to http://localhost:8083 dynamically
4. [Order ➔ Restaurant] OpenFeign client queries item prices and stock availability
5. [Order ➔ Payment] OpenFeign client authorizes transaction charge ref
6. [Database Commit] Order persisted into PostgreSQL 'orders' & 'order_items' (Atomic Transaction)

1. Problem Analysis & Requirement Specification

Deep analysis and Complete Structure

  • Domain Decomposition: Consumers, Kitchens, Logistics Fleets.
  • State Machine: PENDING $\rightarrow$ CONFIRMED $\rightarrow$ PREPARING $\rightarrow$ DELIVERED.
  • Resilience: Stock depletion validation & payment rollback logic.
Level 510 / 10 Weightage

2. Microservice Identification & Service Discovery

Highly Modular Design

  • Eureka Registry (:8761): Heartbeat monitoring and dynamic service discovery.
  • Service Isolation: 6 autonomous services for Auth, Menu, Order, Payment, Gateway, Eureka.
  • OpenFeign Orchestration: Inter-service communication with client-side load balancing.
Level 510 / 10 Weightage

3. JWT Authentication

Robust and Secure

  • Email Authentication: BCrypt password encryption (no plain passwords in DB).
  • Signed Tokens: HMAC-SHA256 signature containing claims (email, role, userId).
  • RBAC Enforcement: Distinct workflows for CUSTOMER vs RESTAURANT_OWNER.
Level 510 / 10 Weightage

4. API Gateway Configuration

Optimized and Secure

  • Unified Entrypoint (:8080): Reverse proxy with dynamic path routing (lb://*).
  • Gateway JWT Filter: Signature validation and request header enrichment before downstream forwarding.
  • Global CORS: Preflight negotiation for smooth frontend requests.
